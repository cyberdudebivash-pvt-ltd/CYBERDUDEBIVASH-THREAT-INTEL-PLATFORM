## 1. Tiers — real enforcement, one clear single-source-of-truth violation

`config/subscription_tiers.json` is explicitly self-declared as authoritative: *"THIS IS THE SINGLE
SOURCE OF TRUTH for all subscription tier definitions... DO NOT duplicate tier definitions in Worker
CONFIG or frontend."* It defines real, detailed FREE/PRO/ENTERPRISE/MSSP tiers with concrete
differentiators (FREE: 100 calls/day, no STIX/AI/IOC visibility; PRO: **$49/mo**, 5,000 calls/day,
STIX + partial AI + IOC visible + dark web + CSV export). This is consumed live: `TIERS` constant +
`enforceTierGate()`/`applyTierGateV2()` (`revenue-enforcement.js`, imported at `index.js:95`) gate
real capabilities per tier in the live request path.

**RESOLVED 2026-09-06 (PR #380).** `revenue-engine`'s duplicate `TIERS`/price tables were
reconciled to `config/subscription_tiers.json`. Re-verified live during the 2026-09-07 production
release audit: `python3 scripts/pricing_consistency_gate.py` → `PASS (0 known warning(s), 0
failures)`. No further action required; left here as a resolved-record, not an open item.

## 5. Upgrade flow — real, with one documented live defect

`upgrade.html` is a fully built, live plan-selector/checkout page (Razorpay + Gumroad integration).
Server-side upsell CTAs are generated by `buildUpgradeTrigger()` in `revenue-enforcement.js`,
embedded directly in gated API responses — a real, functioning upsell loop, not just a static page.

One specific defect, previously documented by the platform's own first-party audit
(`docs/BILLING_ENTITLEMENT_ARCHITECTURE_AUDIT.md`, 2026-08-03) and independently re-confirmed
**still open** during the 2026-09-07 production release audit:
- **The trial endpoint 404s from its own promoted URL**: `POST /api/leads/trial` only works on
  `revenue.intel.cyberdudebivash.com`. `js/trial_conversion_engine.js` is the only caller and is not
  `<script>`-included by any HTML page in this repository (`grep -rl trial_conversion_engine
  --include=*.html .` → zero matches) — the self-serve trial funnel is fully dead code, unreachable
  from the live site. Low severity for a hand-provisioned enterprise deal (this launch's path is
  `contact-enterprise.html` → `scripts/customer_onboard.py`, not the self-serve trial), but real for
  inbound self-serve leads. Recommended fix: either wire `trial_conversion_engine.js` into the pages
  that should offer a trial, or remove the dead endpoint/script and the promotional trial copy that
  references it.
- ~~`provisionApiKey()`'s revenue-integrity fix ships disabled by default~~ — **RESOLVED**, see §6.

## 6. Revenue-integrity finding — RESOLVED 2026-09-03

`provisionApiKey()` (`index.js:2421-2443`) previously hardcoded `expires_at: null` on every
provisioned key — meaning a single one-time Razorpay Order or Gumroad sale granted **permanent**
API access regardless of the monthly/annual price actually paid. Fix (tagged `P2.7-001`,
"shadow-mode expiry"): `resolveAuth()` checks `expires_at` and downgrades to FREE once past; the
write only took effect when `env.SUBSCRIPTION_EXPIRY_ENABLED === "true"`. **Re-verified live during
the 2026-09-07 production release audit**: `workers/intel-gateway/wrangler.toml` now sets
`SUBSCRIPTION_EXPIRY_ENABLED = "true"` at both the top-level `[vars]` and `[env.production.vars]`
blocks (flipped in commit `b95242ca`, 2026-09-03), and `index.js:3792` confirms the enforcement
condition (`enforceExpiry = validTier !== "FREE" && env.SUBSCRIPTION_EXPIRY_ENABLED === "true"`)
reads that flag directly. Paid-tier keys provisioned today do get a real, enforced expiry. No
further action required; left here as a resolved-record, not an open item.

## 7. Billing integration

Two live payment paths, one dormant:
- **Razorpay: real and live.** `upgrade.html`'s `initiateRazorpayCheckout()` calls a confirmed-live
  endpoint (`POST /api/payment/razorpay/create-order`, verified against production per
  `docs/BILLING_ENTITLEMENT_ARCHITECTURE_AUDIT.md` returning real 200 order responses). A
  subscription webhook exists (`workers/revenue-engine/src/subscription-engine.js`,
  `/api/v2/billing/webhooks/razorpay`) but is **"correct, dormant"** per the same audit — checkout
  only creates one-time Orders, never a Razorpay Subscription object, so the webhook path never
  actually fires.
- **Gumroad: real and live** — direct purchase links (`cyberdudebivash.gumroad.com`), webhook-driven
  key auto-provisioning.
- **Stripe: coded but unconfigured.** `scripts/stripe_billing_engine.py`, `stripe_webhook.py`,
  `stripe_revenue.py` and API-side handlers all exist, but the platform's own audit
  (`GODMODE-REVENUE-AUDIT-REPORT.html`) states plainly: payment-link environment variables are not
  configured and "Zero automated revenue flow" exists through this path.
