`enterprise-knowledge-center.html` is the platform quality, search, and
release-readiness layer &mdash; the fifth page in the enterprise family
(`enterprise-homepage.html` PR-5, `enterprise-pricing.html` PR-6,
`enterprise-compliance.html` PR-7, `developer-portal.html` PR-8),
consuming `css/tokens.css` (PR-2) and `css/components.css` (PR-4) only.
Unlike PR-5&ndash;8, this PR is explicitly **not** another marketing
page: its job is discoverability, documentation consistency,
navigation unification, and transparent disclosure of repository
drift.

**Status:** new, standalone page, now linked from all 4 existing
enterprise-family pages' nav and footer, and the sole page to
introduce a unified navigation fix across the whole family (see
Navigation Architecture, below).

## 2. Navigation Architecture (Information Architecture)

### 2.1 What was found

The audit discovered that the enterprise-family nav had already
diverged into two different shapes before this PR:

| Pages | Nav shape (6 items, pre-PR-9) |
|---|---|
| `enterprise-homepage.html`, `enterprise-pricing.html` | Platform / Threat Intelligence / Developers / **Documentation** (`/docs/`) / **Research** (`/blog/`) / Pricing / Enterprise &mdash; no Trust Center |
| `enterprise-compliance.html`, `developer-portal.html` | Platform / Threat Intelligence / Developers / Pricing / **Trust Center** / Enterprise &mdash; no Documentation or Research |

This happened because Trust Center was introduced in PR-7 directly
into `enterprise-compliance.html`'s own nav (and copied into
`developer-portal.html`'s nav when PR-8 built that page from the same
template), but the two earlier pages' primary nav was never
back-ported &mdash; only their *footer* got a Trust Center link (the
"3 href changes" and "6 href changes" PR-7/PR-8 each made were footer
and cross-page link changes, not primary-nav changes).

### 2.2 What this PR does about it

Per this PR's explicit "Create a unified navigation structure. Ensure
every enterprise page links consistently" objective, all 5
enterprise-family pages (the 4 existing plus this new one) are now
unified onto one identical 7-item primary nav:

```
Platform -> /index.html
Threat Intelligence -> /threat/
Developers -> /developer-portal.html
Pricing -> /enterprise-pricing.html
Trust Center -> /enterprise-compliance.html
Enterprise -> /enterprise-homepage.html
Knowledge Center -> /enterprise-knowledge-center.html
```

`enterprise-homepage.html` and `enterprise-pricing.html` had their top-nav
"Documentation" and "Research" links replaced by "Trust Center" and
"Knowledge Center." **Nothing becomes unreachable**: `/docs/` and
`/blog/` remain linked from every page's footer Resources column
(unchanged) and are now additionally surfaced in this page's own
Documentation Index and Search Hub. This is judged a non-breaking,
purely presentational consolidation, not an architectural event &mdash;
no route, schema, or backend behavior changes.

The footer "Resources" column across all 5 pages was also unified to
the same 5-item list (Knowledge Center / Developer Portal / API Quick
Start / Research Blog / Trust Center), replacing 3 slightly different
prior variants (see Evidence Matrix &sect;3.6 for the exact before
state).

**Guarded by a dedicated regression test**:
`tests/test_enterprise_knowledge_center.py::test_all_enterprise_family_pages_share_identical_primary_nav`
parses all 5 files' actual rendered nav and fails the build if they
ever diverge again.

### 2.3 What is deliberately *not* fixed

Two further, real gaps are disclosed on the page itself (Navigation
Map section) rather than silently patched, because fixing them would
mean editing files outside this PR's evidence-based scope:

1. `index.html` and 5 legacy pages (`pricing.html`, `trust-center.html`,
   `api-docs.html`, `onboarding.html`, `get-api-key.html`) still do not
   link to any enterprise-family page. Not fixed: `index.html` is a
   protected live dashboard; the other 5 have no defect evidence
   requiring a change, and editing 5 unrelated live pages to add
   outbound links is a materially larger, less-scoped change than this
   PR's mandate.
2. `components/header.html` / `components/navigation.html` (the PR-4
   canonical nav reference) document a 9-link nav with 5 nonexistent
   targets and 1 broken anchor. Not fixed: editing the canonical
   component reference is an architectural event per this repository's
   Architecture Preservation Rule, requiring stronger evidence and
   review than a page-addition task; disclosed instead.

## 6. Known Limitations

- **Breadcrumbs were not added to this page.** A real breadcrumb
  pattern exists elsewhere in the repository (JSON-LD + CSS + `<div>`,
  used on 6+ threat pages and all blog posts), but it is not
  centralized in `css/components.css`, and this page sits at the site
  root alongside its 4 siblings (a "Home &gt; Knowledge Center" trail
  adds no real wayfinding value at that depth). Judged lower-value than
  the Search Hub and Navigation Map for this page specifically;
  disclosed here rather than added just to check a box.
- **The Search Hub is a curated directory, not a full-text index.** It
  covers 31 hand-verified real destinations across 7 categories, not
  all ~140 top-level HTML files in the repository. Building a true
  full-site search index was judged out of scope for this PR (no
  existing search-index infrastructure to extend, and fabricating
  page-relevance rankings for 140 unaudited files risks surfacing
  something inaccurate). The Documentation Index and this page's own
  links reach every genuinely relevant destination for this PR's
  scope.
- **The Changelog Explorer's "Released" column is blank wherever a
  file's own header did not state a date** &mdash; shown as "Not stated
  in header" rather than guessed.
- **None of the Known Repository Drift Dashboard's disclosed items is
  resolved** by this page (version-number split, 4-page compliance
  status divergence, canonical-nav-vs-shipped divergence, sitemap gaps)
  &mdash; all require either a human with access to the actual
  production configuration, or a decision to edit `scripts/seo_domination.py`
  / `components/header.html`, both judged out of this PR's scope.
- **No automated pixel-diff visual regression harness** &mdash; same
  disclosed limitation as PR-5&ndash;8.
- **Playwright is not a project dependency** &mdash; same as PR-5&ndash;8.
